# Quick Task 260503-k8k -- Wire ClvRecorder + OddsApiClient into the scheduler

## Objective

Replace the logging-only `_record_clv` stub in `PipelineOrchestrator` with a real
CLV snapshot path that:

1. Looks up the Pinnacle event_id from a fixture via The Odds API (using
   `OddsApiClient.find_event_by_fixture`, new helper added in Task 1).
2. Fetches Pinnacle closing odds for the relevant market.
3. Persists the result via `ClvRecorder.record(...)`.
4. Schedules the snapshot at `kickoff - 1 minute` (NOT `kickoff + 105 minutes`)
   so we capture the actual closing line right before kickoff (the price freezes
   at kickoff on Pinnacle h2h).

`_reconcile_clv` becomes a Phase-4 placeholder with an explicit deferral comment
and a single `logger.warning(...)` line; no logic changes.

## Context

- Existing `OddsApiClient.fetch_pinnacle_closing_odds(sport_key, event_id, market_key)`
  is event-scoped — but the orchestrator only knows the API-Football fixture id.
  We need a small `find_event_by_fixture` helper that calls
  `/v4/sports/{sport_key}/events`, matches on `home_team` + `away_team`
  (case-insensitive contains) and `commence_time` within ±2h of `kickoff_utc`,
  and returns the Odds API event id (or `None` when no match).
- `ClvRecorder.record(...)` requires a `pick_id`. For Phase 3 we look up the most
  recent **pending** 1X2 pick for the fixture via
  `pick_repo.get_pending_for_fixture(fixture_id)` and snapshot one CLV row per
  pending 1X2 pick. No pending picks → log + return cleanly (no crash).
- `OddsApiClient.fetch_pinnacle_closing_odds` returns the Pinnacle bookmaker dict;
  we need to project its `markets[0].outcomes[*]` list into the
  `{"1": ..., "X": ..., "2": ...}` shape that `ClvRecorder.record` expects. Use
  `home_team` / `away_team` from the fixture to label outcomes deterministically;
  "Draw" → "X".
- `_reconcile_clv` (the nightly cron) is a Phase 4 deliverable
  (rolling-50 trend alerting + back-fill for fixtures with missing snapshots).
  Keep the method, replace the body with a deferral comment + warning log so
  ops can see the cron firing.

## Tasks

### Task 1 — `OddsApiClient.find_event_by_fixture` (TDD)

**RED (test):**

Add 5 new tests in `tests/test_clv_client.py` under a new
`class TestFindEventByFixture:` covering:

1. `test_returns_event_id_on_team_and_time_match` — happy path,
   `/v4/sports/soccer_epl/events` returns one matching event,
   helper returns `"event-uuid-123"`.
2. `test_returns_none_when_no_team_match` — events list returned but no team-name
   match. Helper returns `None`.
3. `test_returns_none_when_time_outside_window` — team match but `commence_time`
   off by 4 hours. Helper returns `None`.
4. `test_team_match_is_case_insensitive` — fixture says `"arsenal"`,
   API says `"Arsenal"`. Helper still matches.
5. `test_api_key_sent_as_query_param` — verify `apiKey=...` query param
   on the upcoming `/events` call.

**GREEN (implementation):**

Add this method on `OddsApiClient`:

```python
async def find_event_by_fixture(
    self,
    *,
    sport_key: str,
    home_team: str,
    away_team: str,
    kickoff_utc: datetime,
    window_hours: int = 2,
) -> str | None:
    ...
```

- Calls `GET /v4/sports/{sport_key}/events` (only `apiKey` param).
- Uses the same retry decorator as `fetch_pinnacle_closing_odds`
  (re-use `_is_retryable_http_error` / wait_exponential / 3 attempts).
- Filters: lowercase contains-match on both team names AND
  `abs(commence_time - kickoff_utc) <= window_hours`.
- Returns first matching `event["id"]`, else `None`.
- Logs `find_event_no_match` (warning) on no match.
