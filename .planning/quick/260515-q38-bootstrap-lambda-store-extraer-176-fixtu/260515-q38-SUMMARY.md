# Phase 260515-q38 Plan 01: Snapshot->History Extractor for Bootstrap Lambda Store Summary

One-liner: CLI script extracts FINISHED Sportmonks club fixtures from raw snapshot cache into
history+fixtures parquets that feed build_lambda_store.py, using the existing fixed parser
(not hand-rolled JSON) and carrying a prominent low-confidence/bootstrap banner.

## What Was Built

`scripts/spike/v3/build_history_from_snapshots.py` walks `<snapshots-root>/<fid>/*.json`,
picks the LAST (lexicographically greatest) file per directory, parses it via
`Fixture.model_validate -> LiveMatchState.from_fixture` (the exact pattern from
`regrade_day4_from_raw.py`), keeps only FINISHED fixtures (`developer_name` in
`{FT, AET, FT_PEN, FINISHED}`), and writes:

- `history.parquet`: `home_team:Utf8`, `away_team:Utf8`, `home_goals:Int64`, `away_goals:Int64`
- `fixtures.parquet`: `fixture_id:Int64`, `home_team:Utf8`, `away_team:Utf8`

Both use parser-derived team-name vocabulary (consistent for build_lambda_store.py cross-reference).
Skip counts (in-progress / parse_error / no_json) are logged. The script prints a prominent
BOOTSTRAP banner twice (start and end) and carries a `# requires-real-data` comment.
