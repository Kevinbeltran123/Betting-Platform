# Quick 260503-j74: Per-Market Edge Thresholds from YAML

One-liner: PickEngine.evaluate now reads per-market edge threshold from the injected LeagueRegistry (8% for 1X2 per premier_league.yaml, 5% BTTS/OU, 6% AH, 7% corners) instead of hardcoding the 5% backtest default for every market.

## What Changed

### `src/bip/core/picks/engine.py`

- **Imports:** added `from bip.sports.football.config.league_registry import LeagueRegistry`.
- **`_NORMALIZE_MARKET` (module-level):** new dict mapping incoming market strings (`1X2`, `onextwo`, `h2h`, `BTTS`, `OU`, `AH`, `CORNERS`) to LeagueConfig.model_params attribute suffix (`1x2`, `btts`, `ou`, `ah`, `corners`). Comment marks G-MAINT-05 as deferred.
- **`PickEngine.__init__`:** added required `league_registry: LeagueRegistry` keyword-only param (no default). Stored as `self._league_registry`. Calling without it raises `TypeError`.
- **`PickEngine.evaluate`:** before calling `simulate_pick`, normalize market via `_NORMALIZE_MARKET.get(market, market.lower())`, then `getattr(league_cfg.model_params, f"edge_threshold_{market_normalized}", EDGE_THRESHOLD_PCT)`. `KeyError` from `LeagueRegistry.get` (unknown league) also falls back to `EDGE_THRESHOLD_PCT`. The resolved `threshold` is passed to `simulate_pick(probs, odds, threshold=threshold)`.
- **Module docstring:** filter chain bullet 1 now reads "simulate_pick edge filter — per-market threshold from LeagueRegistry (G-MAINT-01 / CORE-05). simulate_pick still imported from bip.train.backtest (D-02 no duplication); EDGE_THRESHOLD_PCT remains the fallback default."

### `tests/picks/test_engine.py`

- **`_default_league_registry()` (new module-level helper):** constructs a `MagicMock` whose `.get()` returns a `LeagueConfig`-shaped mock with `model_params` containing only the five real `edge_threshold_*` attributes (via `spec=[...]` so unknown attrs raise `AttributeError` -- this lets `getattr(..., default)` trigger in the unknown-market test).
- **`_make_engine`:** new optional `league_registry` kwarg (defaults to `_default_league_registry()`). Forwards `league_registry=` into `PickEngine(...)`.
- **`TestPerMarketEdgeThreshold` (new class, 5 tests, 7 collected after parametrize):**
  1. `test_engine_uses_per_market_threshold_from_yaml` -- 1X2 pick at 5.6% edge filtered (no_edge) because 8% required.
  2. `test_engine_uses_btts_threshold_from_yaml` -- BTTS pick at 5.6% edge proceeds to validator (CONFIRM -> pending) because 5% threshold.
  3. `test_engine_normalizes_market_alias` -- parametrized over `["1X2", "onextwo", "h2h"]`, all three resolve to `edge_threshold_1x2` and filter ~6% edge.
  4. `test_engine_falls_back_to_default_for_unknown_market` -- market `"unknown_xyz"` with sparse `model_params` falls back to `EDGE_THRESHOLD_PCT` (0.05); pick at 6% proceeds.
  5. `test_engine_constructor_requires_league_registry` (sync) -- omitting the kwarg raises `TypeError`.

### Test-design adjustment (not a code deviation)

- The plan suggested `MagicMock` with bare `.edge_threshold_X = 0.08` assignments. To make the unknown-market fallback test (Test 4) actually exercise `getattr`'s default branch, `_default_league_registry()` and the sparse-config mock both pass `spec=[...]` so accessing an undeclared attr raises `AttributeError` -- this is what `getattr(obj, name, default)` requires to use the default. Without `spec`, MagicMock would auto-create an attr (as another MagicMock) and silently bypass the fallback path, leaving the test passing for the wrong reason.
