# Phase 02.1 Plan 08: feature_schema_version stamp + mixed-read guard Summary

D-08 schema versioning: every new feature row carries `feature_schema_version=2`; reads of Phase 1 data warn instead of crashing.

## Changes

### Task 1 — features.py: stamp feature_schema_version=2

Added a single new key to the `row` dict literal in `FeatureEngineer.to_parquet_row()` immediately after `computed_at`:

```python
"feature_schema_version": [2],   # D-08: Phase 1 data is implicit v1 (absent column)
```

The value is a hardcoded integer literal. No other logic changed. Every DataFrame produced by `to_parquet_row()` now contains this column, so downstream `ParquetStore.write_features()` writes it through the pipeline.

### Task 2 — parquet_store.py: mixed-version guard in read_features

- Added `import structlog` and `logger = structlog.get_logger(__name__)` at module level (these were not present — pure additive imports).
- Modified `read_features()` to capture the `_read()` result, check column presence, and emit a structlog warning when:
  1. The DataFrame is non-empty, AND
  2. The `feature_schema_version` column is absent.

The warning payload includes `league` and `sport` for traceability. Empty DataFrames (no data seeded) intentionally suppress the warning to avoid false alarms during early-test scenarios.

### Test addition

Added `TestFeatureSchemaVersion.test_to_parquet_row_includes_schema_version_v2` to `tests/test_feature_pipeline.py`. Asserts both column presence and value `2`.
