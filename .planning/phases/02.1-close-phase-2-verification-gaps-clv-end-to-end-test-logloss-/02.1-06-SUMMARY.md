# Phase 02.1 Plan 06: ApiFootballClient.get_odds dual-mode dispatch Summary

**One-liner:** Added `get_odds()` to `ApiFootballClient` with per-fixture (live) vs league+season (bulk historical) dispatch, matching the existing tenacity retry stack — unblocks both Phase 3 live picks and plan 02.1-09 historical seeding.

## What was built

A single new async method `ApiFootballClient.get_odds(fixture_id=None, league_id=None, season=None, bookmaker="Betano")` (~30 LOC) that:

- Sends `GET /odds?fixture={id}` when `fixture_id` is provided (Phase 3 live use; API-Football's 7-day lookback applies)
- Sends `GET /odds?league={lid}&season={year}` when `league_id` + `season` are provided (bulk historical seeding for plan 02.1-09)
- Raises `ValueError` if neither is provided — fail-fast on misuse rather than emit a malformed request
- Wears the identical `@retry(retry_if_exception=is_retryable_http_error, wait=wait_exponential(min=2, max=60), stop=stop_after_attempt(5), reraise=True)` decorator as `get_fixtures`, `get_lineups`, `get_statistics`, `get_injuries`, `get_h2h` — ops monitoring sees one consistent retry signature
- Logs only `endpoint` + `params` (integer IDs); api_key stays in the `x-apisports-key` header set during `__init__`

Three unit tests cover the contract (`tests/test_apifootball_get_odds.py`):

1. `test_get_odds_fixture_mode` — mocks 200 response, verifies `fixture=12345` is in the URL and `response` key is in the return dict
2. `test_get_odds_bulk_mode` — verifies `league=39` and `season=2024` both in URL
3. `test_get_odds_rejects_neither` — verifies `ValueError` containing "fixture_id" raised on no-args call

## How it works

**Dispatch logic** (mutually exclusive — caller picks one mode):

```python
if fixture_id is not None:
    params = {"fixture": fixture_id}
elif league_id is not None and season is not None:
    params = {"league": league_id, "season": season}
else:
    raise ValueError("get_odds: pass either fixture_id or (league_id, season)")
```

The `bookmaker` keyword exists for caller readability (`client.get_odds(fixture_id=42, bookmaker="Betano")` reads cleanly) but is **not** forwarded to the API — API-Football's `/odds` endpoint returns every bookmaker it has data for; filtering is the caller's job downstream.

**Why no Pinnacle-specific logic here?** This client is for API-Football (which carries Betano + other regional books). Pinnacle CLV anchors come from `OddsApiClient` (a separate module). Keeping `get_odds` source-agnostic at the client level — caller chooses bookmaker.
