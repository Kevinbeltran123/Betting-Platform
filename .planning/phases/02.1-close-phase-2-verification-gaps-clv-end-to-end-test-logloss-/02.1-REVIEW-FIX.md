## Fixed Issues

### CR-01: Per-fixture writes to results/ and odds/ Parquet stores wipe prior partition data

**Files modified:** `src/bip/core/storage/parquet_store.py`, `scripts/seed_historical.py`, `tests/test_parquet_store_results_odds.py`
**Commit:** c7bf71e
**Applied fix:** Added an `overwrite: bool = True` kwarg to `ParquetStore._write` (and the public `write_results` / `write_odds` wrappers). Default `True` preserves the existing batch-write tests; `overwrite=False` reads the existing partition rows from disk, concatenates the incoming rows, deduplicates on `fixture_id` (or `(fixture_id, bookmaker)` for the odds store) keeping the latest row, then rewrites the partition. `seed_historical.py` now passes `overwrite=False` to both `write_results` and `write_odds` so per-fixture writes inside `seed_one_league` no longer `shutil.rmtree` every prior fixture in the same partition. Added 4 regression tests: per-fixture append for results, per-fixture append for odds, default overwrite still replaces partition (regression guard for existing tests), and per-fixture results dedup on repeat fixture_id.

### WR-01: pipeline.run() crashes with cryptic Polars error on fresh installs

**Files modified:** `src/bip/train/pipeline.py`
**Commit:** 9981044
**Applied fix:** Added explicit empty-store guards before the results/odds joins. Empty `pl.DataFrame()` returns from `read_results()` / `read_odds()` now raise `RuntimeError(f"No results rows for league={league}. Run scripts/seed_historical.py first.")` (and likewise for odds) before `pl.col("status")` / `pl.col("bookmaker")` can hit a zero-column DataFrame and emit a `ColumnNotFoundError` traceback.

### WR-02: derive_db_url() does not URL-encode the password

**Files modified:** `scripts/verify_migration_003.py`
**Commit:** 5ea19d2
**Applied fix:** Imported `urllib.parse.quote` and wrapped `db_password` with `quote(db_password, safe='')` inside `derive_db_url`. Special characters (`@`, `#`, `!`, `?`, `/`, `:`, `%`) are now percent-encoded so the userinfo component cannot be split prematurely. Also switched `db_url.split("@", 1)[-1]` to `db_url.rsplit("@", 1)[-1]` so the sanitized-host log line splits on the LAST `@` (the userinfo/host delimiter) rather than the first, providing defense in depth against any future caller that bypasses `derive_db_url`.

### WR-03: seed checkpoint accounting drifts from the partition store on every restart

**Files modified:** `scripts/seed_historical.py`, `tests/test_seed_checkpoint.py`
**Commit:** 0101901
**Applied fix:** Added a `CHECKPOINT_SCHEMA_VERSION = 1` marker. `save_checkpoint` writes the version field; `load_checkpoint` resets `completed_results_fixture_ids` and `completed_odds_fixture_ids` to empty sets when the on-disk file is missing the version (or carries a lower one) — i.e. when the checkpoint was written by the pre-CR-01 code path whose partition writes silently destroyed prior fixtures. The features tracking set is preserved (the features write path was never affected by CR-01). Added 2 regression tests: pre-CR-01 checkpoint resets results/odds, post-CR-01 checkpoint round-trips with version intact.

### WR-04: _parse_matchday returns 0 for non-numeric rounds

**Files modified:** `scripts/seed_historical.py`
**Commit:** bd469d2
**Applied fix:** Changed `_parse_matchday`'s return type from `int` to `int | None` and `return None` on parse failure. The seed loop now skips fixtures whose round string is non-numeric (cup ties, play-offs) with a `seed_skip_unparseable_round` structured log breadcrumb instead of lumping every such fixture into a single `matchday=0` Hive partition.

### WR-05: _pressing_tactical overwrites stat values when API returns multiple matching type strings

**Files modified:** `src/bip/sports/football/features.py`
**Commit:** 7559f35
**Applied fix:** Replaced the substring `in` matchers with exact-string equality against an explicit whitelist (`"total shots"`, `"ball possession"`, `"corner kicks"`). The lookup is now order-independent and robust to future "*-like" stat names (`"Shots insidebox"`, `"Corner Kicks Conceded"`) that previously silently overrode the canonical value.

### WR-06: SQL DEFAULT now() vs Pydantic nullability mismatch

**Files modified:** `src/bip/core/storage/models.py`
**Commit:** c3a3ece
**Applied fix:** Two-part fix:
1. `OddsSnapshot.to_supabase_dict()` now always emits a concrete `captured_at` (defaulting to `datetime.now(UTC)` when the caller did not supply one). The server-side `DEFAULT now()` cannot fire and produce a timestamp that disagrees with the Python-side capture time, preserving CLV's "captured at exactly T+105m" semantic.
2. Added `model_config = ConfigDict(extra="ignore")` to `Prediction`, `Pick`, `OddsSnapshot`, `Result`, `ClvRecord`, and `PerformanceMetric`. Every one of these tables has a server-defaulted `created_at` column with no Pydantic counterpart; `extra="ignore"` lets `Model.model_validate(row)` round-trip without raising on the extra column when Phase 3 consumers read rows back from Supabase.
