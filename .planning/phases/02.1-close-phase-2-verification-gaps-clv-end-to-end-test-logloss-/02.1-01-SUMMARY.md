## Decisions Made

- **Used Supabase MCP, not supabase CLI** — the user did not have supabase CLI authenticated/linked in this session; the MCP `apply_migration` and `execute_sql` tools provide an equivalent platform-API path that writes the same `supabase_migrations.schema_migrations` row. The CLI path remains the canonical local workflow (the verify script supports it directly); future contributors can use either.
- **Reconstructed migration 001 from Pydantic models, not a DB dump** — no DB dump existed for the upstream project, and copying from Football_analysis would conflate two separate codebases. Pydantic models + REQUIREMENTS.md gave a deterministic single-source-of-truth reconstruction.
- **Omitted `sport`, `is_shadow`, `odds_fetched_at` from 001** — those columns are added by 002/003 and squashing them would obscure the migration audit trail. Replaying 001 → 002 → 003 yields the exact same end-state with full history.
- **Kept `SUPABASE_DB_PASSWORD` out of pydantic-settings** — Settings.repr would expose it in logs/tracebacks. `os.environ.get()` keeps the secret confined to a single function call.
