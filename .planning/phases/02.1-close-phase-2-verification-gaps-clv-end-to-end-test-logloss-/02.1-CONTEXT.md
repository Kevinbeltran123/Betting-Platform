<decisions>
## Implementation Decisions

### Opening-odds source

- **D-01:** Dual-source architecture lands in 02.1: `ApiFootballClient.get_odds()` for opening (Betano-staked) + Pinnacle closing via `OddsApiClient.fetch_historical_closing()`. Plumbing for both is built this phase; **only the API-Football path is exercised**. `pinnacle_close_home/draw/away` columns are present but nullable; actual Pinnacle /historical backfill is deferred to a follow-up task after the API-Football side produces clean CLV numbers.
- **D-02:** Staked opening odds = Betano decimal odds from API-Football `/odds` endpoint. Closing-side proxy = last pre-kickoff Betano snapshot (same endpoint, latest capture). CLV formula in `backtest.compute_clv` stays unchanged; the "closing" input is the proxy until Pinnacle is retrofitted.
- **D-03:** Fixtures where Betano opening odds are missing from the API-Football response are **skipped from CLV computation** (not fail-fast, not imputed). `ModelMetadata.null_clv_rows` increments for coverage transparency. Row is still used for label/training, just not CLV.

### Parquet schema

- **D-04:** `home_goals`/`away_goals` and `opening_home/draw/away` + nullable `pinnacle_close_home/draw/away` live in **separate Parquet stores joined by `fixture_id` at read time**:
  - `features/{sport}/{league}/{season}/{matchday}/*.parquet` — unchanged from Phase 2 (with one addition: `feature_schema_version: int` column).
  - `results/{sport}/{league}/{season}/*.parquet` — new: `fixture_id, home_goals, away_goals, status` (where `status` indicates finished / abandoned / postponed for downstream filtering).
  - `odds/{sport}/{league}/{season}/*.parquet` — new: `fixture_id, bookmaker, opening_home/draw/away, closing_home/draw/away, pinnacle_close_home/draw/away` (last three nullable in 02.1).
- **D-05:** `TrainingPipeline.run()` adds a `store.read_results(league)` + `store.read_odds(league)` step and joins both onto the feature DataFrame on `fixture_id` before label derivation. The existing `if "home_goals" not in df.columns` guard at `pipeline.py:60-64` is replaced by a pre-join contract: pipeline raises if the join produces zero rows (data pipeline failure, not schema failure).
- **D-06:** Match results are fetched **per-fixture during the main seed loop** — `item["goals"]["home"]/["away"]` is already in the `/fixtures` response payload for finished matches. Zero extra API calls beyond what Phase 2's seed already does.
- **D-07:** New `ApiFootballClient.get_odds(fixture_id: int, bookmaker: str = "Betano") -> dict | None` method returns `{"opening": {"1": 2.10, "X": 3.40, "2": 3.20}, "closing_proxy": {...}}` or `None` if the bookmaker isn't in the response. Used by both the seed script (historical) and Phase 3 prediction path (live).
- **D-08:** `feature_schema_version: int` column added to every feature Parquet row. Phase 1 data is implicit v1 (absent column → v1 on read); Phase 02.1 seeds v2. `ParquetStore.read_features()` warns on mixed versions within a read.

### CLV computation semantics

- **D-09:** Per test row, `walk_forward_mean_clv_pct` is computed against the **simulated EV pick**: for each of the three outcomes `o ∈ {home, draw, away}`, compute `edge = model_prob[o] × opening_odds[o] - 1`. If `max(edge) >= 0.05`, select that outcome and compute `clv_pct = compute_clv(apply_slippage(opening_odds[o_selected]), closing_proxy[o_selected])`. If `max(edge) < 0.05`, the row contributes nothing to CLV. This mirrors Phase 3's PICK-01 EV filter exactly.
- **D-10:** Edge threshold is a **shared constant** `EDGE_THRESHOLD_PCT = 0.05` in `bip.train.backtest` (new module-level constant alongside `SLIPPAGE_PCT`). Phase 3's pick engine will import the same constant. Single source of truth so backtest CLV and production picks move together if the threshold is ever tuned.
- **D-11:** A fold contributes to `walk_forward_mean_clv_pct` only if it produced **≥ 20 simulated picks**. Folds with fewer picks get `fold_details[i]['clv_pct'] = None` and are excluded from the mean. The excluded test rows increment `null_clv_rows` for transparency.
- **D-12:** Markets in 02.1 backtest CLV = **1X2 only** (Home/Draw/Away). Matches the Phase 2 StackedEnsemble 3-class softmax. BTTS / O/U 2.5 / corners are out of scope (deferred — they need separate model heads).

### Logloss persistence (Criterion 2)

- **D-13:** `ModelMetadata` gets three new scalar fields: `logloss_uncalibrated: float`, `logloss_calibrated: float`, `logloss_improvement_pct: float` (= `(logloss_uncalibrated - logloss_calibrated) / logloss_uncalibrated × 100`). Computed on the last fold's test window (the same slice `calibrator` is fit on) via `sklearn.metrics.log_loss`.
- **D-14:** `walk_forward_fold_details` entries get a parallel `logloss_calibrated` / `logloss_uncalibrated` pair per fold (computed from the fold's test-slice predictions). Enables cross-fold inspection without requiring re-training.

### Scope / exit criteria

- **D-15:** Migration 003 application to **live Supabase is an exit criterion** for 02.1. Exit check: `SELECT column_name FROM information_schema.columns WHERE table_name='predictions' AND column_name='is_shadow'` returns one row; `SELECT indexname FROM pg_indexes WHERE tablename='predictions' AND indexname='idx_predictions_is_shadow'` returns one row. Closes the Phase 2 blocking human checkpoint.
- **D-16:** Phase 02.1 is not complete until a **real end-to-end smoke train of the Premier League** produces a `models/football/premier_league/v1/metadata.json` where `walk_forward_mean_clv_pct` is a non-zero float, at least 3 of 5 folds have non-`None` `clv_pct`, and `logloss_improvement_pct > 0`. Command sequence:
  - `uv run python scripts/seed_historical.py --seasons 2024-2025 --leagues premier_league`
  - `uv run python -m bip.train fit --league premier_league --version v1`
- **D-17:** Phase 02.1 ships **both** a synthetic-data pytest integration test (runs on every commit — `tests/test_training_pipeline_e2e.py`) **and** the real single-league smoke train (one-shot exit check). Synthetic gates commits; real gates phase exit.

- Whether `get_odds()` uses API-Football `/odds?fixture={id}` (per-fixture) or `/odds?league={id}&season={season}` (bulk per season) for the seed — optimize whichever consumes fewer rate-limit tokens.

<specifics>
## Specific Ideas

- The `_EnsembleProbaWrapper` "wart" at `pipeline.py:113-141` (noted in verification report as a Warning — `fit_fold` re-runs on a tiny slice to satisfy FrozenEstimator's API contract) **is not fixed in 02.1**. It's a separate refactor and works correctly; Criterion 2's logloss delta is computed on the already-wrapped output, so no regression.
- The `data/seed_checkpoint.json` must track **completed odds + results fetches separately** from fixture completion — a fixture may have features but no odds response; the checkpoint JSON grows one nested set per data type (`completed_fixture_ids`, `completed_odds_fixture_ids`, `completed_results_fixture_ids`).
- Premier League smoke train target: 2024-2025 season only, one league, ~380 fixtures, ~10-15 min wall time on API-Football Pro plan (380 fixtures × 4 calls = 1,520 calls at 300/min = ~5 min API time + fixture-processing overhead).
- The planner should expect `fold_details[i]['clv_pct']` to be `None` in synthetic tests (synthetic data doesn't have real opening odds) — the integration test should assert the *wiring* (function gets called, metadata field populated with either a float or None per fold) rather than asserting a specific non-zero CLV value.
- Migration 003 application **must** run against the user's live Supabase project (credentials in `.env`) — the exit check is a read-only `information_schema` query that the planner can wrap as a `make verify-migration-003` target or a `scripts/verify_migration_003.py` script.

</specifics>
