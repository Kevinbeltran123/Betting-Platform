# Phase 02.1 Plan 09: seed_historical results + bulk odds + 3-key checkpoint Summary

**Extended seed_one_league() to write match results from /fixtures payload (zero extra calls) and Betano 1X2 odds via a single bulk /odds call per (league, season), backed by an independently-gated 3-key checkpoint with Phase 2 backward-compat.**

## Accomplishments

- `seed_one_league()` now writes three independent Parquet stores (features / results / odds) in a single pass over the season's fixtures.
- Bulk `client.get_odds(league_id=..., season=YYYY)` fetched once per (league, season) — keyed into `odds_by_fixture` dict for O(1) per-fixture merge inside the existing per-day loop.
- Match results extracted from the existing `/fixtures` response payload (`item["goals"]["home"]` / `away` + `item["fixture"]["status"]["short"]`) — zero extra API calls (D-06).
- Checkpoint expanded from single set to 3-key dict (`completed_fixture_ids` / `completed_results_fixture_ids` / `completed_odds_fixture_ids`) with deterministic sorted serialization and Phase 2 backward-compat (legacy single-key file loads cleanly).
- `ALLOWED_LEAGUE_SLUGS` frozenset enforced at seed_one_league() entry — raises ValueError before any API call or Parquet write (T-02.1-04 mitigation).
- `_parse_odds_entry()` helper extracts Betano "Match Winner" with closing-proxy = opening (D-02), null Pinnacle columns (D-04), and rejects partial markets (Match Winner missing any of Home/Draw/Away returns None).

## Files Created/Modified

- `scripts/seed_historical.py` — added `polars` import, 3-key checkpoint helpers (`load_checkpoint`/`save_checkpoint`, `_empty_state`, `CHECKPOINT_KEYS`), `ALLOWED_LEAGUE_SLUGS` frozenset, `_ODDS_SCHEMA` + `_parse_odds_entry()` helper, restructured `seed_one_league()` (slug validation → bulk odds fetch → per-fixture results extraction → per-fixture odds write → existing features pipeline), updated `main()` to log per-artifact resume counts.
- `tests/test_seed_checkpoint.py` — updated `test_checkpoint_resume` and `test_checkpoint_atomic_write` to dict shape, updated `test_checkpoint_empty_when_missing` to assert on 3-key empty dict, added `test_checkpoint_backward_compat_with_old_shape` covering Phase 2 single-key file load.

## Decisions Made

- **Combined task commit:** Tasks 1 and 2 both modify the same checkpoint helpers and `seed_one_league()` body. Splitting them into two commits would have produced an intermediate commit where `seed_one_league()` still passed `completed: set[int]` against the new dict-typed helpers — breaking the build between commits. Single atomic commit preserves a green-build invariant on every commit in the history.
- **Sorted checkpoint payload:** `sorted(state.get(key, set()))` on write produces a stable on-disk JSON diff so a `git diff data/seed_checkpoint.json` after each batch shows the 25-fixture delta cleanly.
- **`get_odds(... bookmaker="Betano")` kwarg passed through:** The `bookmaker` parameter is documented as informational on the client (not sent to API-Football). Passing it from the seed makes the intent explicit at the call site even though the client filters bookmakers downstream.
